# Pocket Heist

Starter project for the Claude Code Masterclass.

## Getting Started

Install dependencies:

```bash
npm install
```

Run the development server:

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) to view the app.


These are the specs for the project:


For auth-state-management
```
/spec let's spec an auth state management solution for the app, where we can access the current user (null if logged out, the user object if logged in) - through a hook called useUser. We should be able to use that hook in any page or component. Then we can update any place in components which currently accesses the user. Do not spec any signup/login/logout flow yet, just a realtime global listener to update user status.
```


For signup-firebase-integration
```
!/spec I want to hook the signup form in @app/(public)/signup/ to firebase auth, using @lib/firebase/config.ts exports. Upon successful signup, the displayName of the user should be set - this should be randomly generated by picking a word from 3 different sets of unique words and jamming them together in Pascalcase. The user should also have a document created in a 'users' collection, to store their displayName (call it codename) and id (but NOT their email). Only use the firebase web sdk.
```

For logout-button
```
/spec Let's spec the logout functionality. We need a logout button in the navbar component, which signs the user out when they click on it. The button should only show when the user is logged in. No Beed for redirects yet. Figma: https://www.figma.com/design/uIo2S2lzu1PcYaOmHCCmOn/ClaudeCodeMasterClass?node-id=57-18&t=y7AtSNdn7XU3RyeX-4
```


For login-form-functionality
```
/spec Can we spec the login form functionality in @app/(public)/login/ - users should be logged in with the correct credentials when submitting the login form, and then shown a success message. No redirect needed for now.
```


For route-protection-auth-guards
```
/spec Let's spec some route protection. Pages in the (public) group should only be viewable to unauthenticated users, and pages in the (dashboard) group should only be viewable to authenticated users. Use the useUser hook to conditionally redirect users. Let's also show a very simple loader in the group layouts until the auth status is identified from firebase and the redirects kick in.
```

To use skill firestore-schema
```
Can you set up types/schemas for heist firestore documents? Heists must have a title, description, createdBy (uid), createdByCodename (their codename/displayName), assignedTo (uid), assignedToCodename (their codename), deadline (a Date, 48 hours from when it was created), finalStatus (null to begin with, then either success or failure in the future).
```

To use plugin frontend-design
```
Can you design a better welcome/splash page for new users to the site, who don't yet have an account. It should have a 'register' button directing to /signup. The page is @app/lpublic)/page.tsx. Keep it in line with the current theme/colours.
```

For create-heist-form
```
/spec let's spec out the 'create heist' form in @app/(dashboard)/heists/create/page.tsx. When the form is submitted, it should create a new heist document in a firestore heists collection, and then redirect the user to the /heists page. Codenames and user ids can be fetched from the users collection, so that users can assign the heist to other users. Use the CreateHeistInput interface for input fields. createAt and deadline values added programatically.
```
